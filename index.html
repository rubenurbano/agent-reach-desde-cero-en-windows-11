Introducción: qué vamos a conseguir

Al terminar este tutorial vas a tener, en tu propio ordenador con Windows 11:

  1. Un ordenador preparado con todo lo que Agent Reach necesita para funcionar.
  2. Agent Reach instalado y comprobado con su propio "chequeo médico" (agent-reach doctor).
  3. Tu primer resultado real: tu agente de IA leyendo una página web y un repositorio de GitHub sin que tú hayas escrito ni una línea de código.
  4. Entendimiento de qué hace cada una de las 15 capacidades que Agent Reach ofrece hoy, con ejemplos que puedes copiar y ejecutar.
  5. Capacidad para diagnosticar y arreglar los problemas más comunes.
  6. Un pequeño proyecto final en el que combinas varias capacidades para conseguir algo útil de verdad.

No hace falta que sepas programar. Vamos a construir todo paso a paso, comprobando en cada momento que lo que hicimos funcionó antes de seguir.

Qué es Agent Reach

Agent Reach no es una aplicación con ventanas ni un programa que tú manejas directamente. Es una caja de herramientas para tu agente de inteligencia artificial (por ejemplo Claude Code, Cursor, Windsurf o cualquier otro agente que pueda ejecutar comandos en una terminal).

El problema que resuelve

Un agente de IA normal, si le pides "búscame en Reddit si alguien ha tenido este mismo error" o "resume este vídeo de YouTube", no puede hacerlo por sí solo. Cada plataforma (Twitter, Reddit, YouTube, GitHub, Bilibili, XiaoHongShu...) tiene sus propias barreras: APIs de pago, bloqueos a servidores, necesidad de iniciar sesión, páginas que devuelven código HTML ilegible en vez de texto limpio.

Lo que hace Agent Reach

En vez de que tú (o tu agente) tengáis que investigar, instalar y configurar una herramienta distinta para cada plataforma, Agent Reach:

  • Elige la mejor herramienta disponible para leer o buscar en cada plataforma.
  • La instala en tu ordenador.
  • Comprueba que funciona de verdad (no solo que el programa esté instalado, sino que responde).
  • Si una herramienta deja de funcionar porque la plataforma cambió algo, la sustituye por otra sin que tengas que hacer nada.

Una vez instalado, tu agente de IA llama directamente a esas herramientas (por ejemplo gh, yt-dlp, bili, twitter). Agent Reach no se pone en medio de cada lectura: solo se encarga de dejarlo todo listo y de decirte, con el comando agent-reach doctor, qué funciona y qué no.

Definición · Terminal Una terminal es una ventana en la que le puedes escribir instrucciones de texto al ordenador, y el ordenador te responde también con texto. En Windows 11 la terminal que vamos a usar se llama PowerShell.

Cómo funciona explicado de forma sencilla

Cuando le pides algo a tu agente de IA que necesita internet, esto es lo que pasa por dentro:

Tú ↓ ("resume este vídeo de YouTube") Tu agente de IA (Claude Code, Cursor, etc.) ↓ Agent Reach ya dejó instalada y comprobada la herramienta correcta ↓ Herramienta real (por ejemplo yt-dlp para YouTube) ↓ Plataforma externa (YouTube) ↓ Resultado (el texto del vídeo) que tu agente te resume

Agent Reach solo interviene en la parte de "dejarlo instalado y comprobado". La lectura real de cada página, vídeo o red social la hace directamente la herramienta correspondiente, llamada por tu agente.

Cada plataforma tiene una lista ordenada de herramientas candidatas: una primera opción y, si falla, una de reserva. Por ejemplo, para Bilibili la primera opción es bili-cli y la de reserva es OpenCLI. El comando agent-reach doctor te dice siempre cuál está usando cada plataforma en este momento.

Preparar Windows 11

En esta sección vamos a comprobar e instalar, uno por uno, cada requisito. Vamos a usar PowerShell como terminal. En Windows 11 la abres así: pulsa el botón de inicio, escribe PowerShell y pulsa Entrar sobre "Windows PowerShell".

Definición · Variable de entorno Es un valor que el sistema operativo guarda en memoria y que los programas pueden leer. Por ejemplo, más adelante guardaremos ahí una contraseña temporal de acceso a Twitter. No hace falta entenderlo del todo ahora; lo explicaremos cuando lo usemos por primera vez.
PASO 1

Comprobar si ya tienes Python instalado

Qué vamos a hacer

Preguntarle a Windows si ya existe una instalación de Python utilizable.

Por qué

Windows 11 a veces trae un "acceso directo" a Python en la Microsoft Store que no es una instalación real. Necesitamos distinguir entre ambos casos antes de seguir.

Acción
py -3 --version
Qué debería ocurrir

Si Python ya está instalado correctamente, verás algo como:

Python 3.12.4

Si en vez de eso se abre automáticamente la Microsoft Store, significa que no tienes Python instalado todavía: lo que existía era solo un acceso directo. Ve al PASO 2.

Prueba

El número de versión debe ser 3.10 o superior. Si es menor, también necesitas instalar una versión más reciente (PASO 2).

Si no ocurre

Si el comando da un error de "no se reconoce como comando", prueba también con:

python --version

Si ninguno de los dos comandos funciona, o si abren la Microsoft Store, continúa con el PASO 2.

PASO 2

Instalar Python 3.10 o superior

Qué vamos a hacer

Descargar e instalar la versión oficial de Python desde python.org.

Por qué

La documentación oficial de Agent Reach advierte específicamente de este problema en Windows: si python3 abre la Microsoft Store, o si where python3 apunta a una ruta dentro de ...\AppData\Local\Microsoft\WindowsApps\python3.exe, esa versión no sirve: es un alias vacío de la Store, no una instalación real. Por eso instalamos Python directamente desde la fuente oficial.

Acción
  1. Abre tu navegador y entra en https://www.python.org/downloads/
  2. Descarga la versión más reciente de Python 3 para Windows.
  3. Ejecuta el instalador descargado.
  4. Muy importante: en la primera pantalla del instalador, marca la casilla "Add python.exe to PATH" antes de pulsar "Install Now". Esto permite que la terminal encuentre Python.
Qué debería ocurrir

El instalador termina y muestra un mensaje de instalación completada.

Prueba

Cierra PowerShell por completo y ábrelo de nuevo (los cambios de PATH no se aplican en la ventana ya abierta). Ejecuta:

py -3 --version

Debe mostrar Python 3.10.x o una versión superior.

Si no ocurre

Si sigue sin reconocerse, vuelve a ejecutar el instalador de python.org, elige "Modify" y comprueba que la casilla de PATH quedó marcada.

PASO 3

Comprobar que pip funciona

Qué vamos a hacer

Verificar que la herramienta pip (el instalador de paquetes de Python) está disponible.

Por qué

pip viene incluido con Python, pero conviene confirmarlo porque es la herramienta que usaremos para instalar el propio Agent Reach.

Acción
py -3 -m pip --version
Qué debería ocurrir

Una línea con un número de versión de pip, por ejemplo pip 24.0 from ....

Prueba

Que aparezca un número de versión sin mensaje de error.

Si no ocurre

Repite el instalador de Python del PASO 2 y asegúrate de no haber desmarcado "pip" en las opciones de componentes (viene marcada por defecto).

PASO 4

Instalar pipx

Qué vamos a hacer

Instalar pipx, la forma recomendada por Agent Reach de instalar su propio comando de línea de órdenes.

Por qué

Cuando instalas un programa de Python con pip a secas, sus dependencias se mezclan con las de todo lo demás en tu sistema, y eso puede romper otras cosas con el tiempo. pipx instala cada herramienta en su propio compartimento aislado. El propio install.md de Agent Reach lo recomienda como opción "más cómoda" (más省心, la que menos preocupaciones da).

Acción
py -3 -m pip install --user pipx
py -3 -m pipx ensurepath
Qué debería ocurrir

Ambos comandos terminan sin errores. El segundo comando añade la carpeta de pipx a tu PATH.

Prueba

Cierra y vuelve a abrir PowerShell, y ejecuta:

pipx --version

Debe mostrar un número de versión.

Si no ocurre

Si pipx no se reconoce tras reiniciar la terminal, ejecuta de nuevo py -3 -m pipx ensurepath y reinicia PowerShell otra vez. La documentación oficial consultada no especifica pasos adicionales para este caso concreto en Windows.

Instalar las herramientas necesarias

Ahora instalamos el resto de piezas que Agent Reach necesita para sus capacidades zero-config (sin configuración): Node.js (para búsqueda web y varias redes sociales) y GitHub CLI (para la capacidad de GitHub).

PASO 5

Comprobar e instalar Node.js

Qué vamos a hacer

Comprobar si tienes Node.js instalado y, si no, instalarlo.

Por qué

Dos piezas clave de Agent Reach —mcporter (que activa la búsqueda semántica en toda la web) y OpenCLI (que da acceso a Reddit, Facebook, Instagram, XiaoHongShu de escritorio y subtítulos de Bilibili)— son programas basados en Node.js. El propio instalador de Agent Reach comprueba la presencia de Node.js como parte de la infraestructura básica.

Acción
node --version
npm --version

Si ambos comandos devuelven un número de versión, ya tienes Node.js y puedes saltar al PASO 6.

Si no:

  1. Ve a https://nodejs.org/
  2. Descarga la versión LTS (la recomendada para la mayoría de usuarios).
  3. Ejecuta el instalador y sigue las pantallas con las opciones por defecto.
Qué debería ocurrir

Tras instalar, ambos comandos muestran un número de versión, por ejemplo v20.14.0 y 10.7.0.

Prueba
node --version
npm --version

Ambos deben responder sin error tras cerrar y reabrir PowerShell.

Si no ocurre

Repite la instalación asegurándote de descargar el instalador .msi oficial de nodejs.org, no una copia de otra web.

PASO 6

Comprobar e instalar GitHub CLI (gh)

Qué vamos a hacer

Comprobar si tienes instalada la herramienta oficial de GitHub para la terminal y, si no, instalarla.

Por qué

La capacidad de leer y buscar en GitHub funciona a través de gh, la herramienta oficial de línea de comandos de GitHub. Es zero-config para repositorios públicos.

Acción
gh --version

Si no está instalado, la forma más simple en Windows 11 es usar el instalador de aplicaciones incluido en el sistema (winget):

winget install --id GitHub.cli
Qué debería ocurrir

gh --version muestra algo como gh version 2.55.0.

Prueba

Cierra y reabre PowerShell y repite:

gh --version
Si no ocurre

Si winget no está disponible en tu equipo, descarga el instalador manualmente desde https://cli.github.com y ejecútalo.

Nota sobre Git y ffmpeg No los instalamos todavía porque no son necesarios para el núcleo de Agent Reach. Los instalaremos más adelante, solo si decides activar Reddit (Git) o la transcripción de podcasts (ffmpeg).
⚙️

Descargar, instalar y probar Agent Reach

Instalar y descargar van juntos en este caso: el comando pip install descarga el código de Agent Reach directamente desde GitHub y lo instala en un solo paso. No hace falta usar Git ni "clonar" nada para tener Agent Reach funcionando: eso solo sería necesario si quisieras modificar su código fuente, algo que este tutorial no cubre.

PASO 7

Descargar e instalar el comando agent-reach

Qué vamos a hacer

Instalar el programa agent-reach en tu sistema usando pipx.

Por qué

pipx (que instalamos en el PASO 4) mantiene esta herramienta aislada del resto de tu sistema.

Acción
pipx install https://github.com/Panniantong/agent-reach/archive/main.zip
Advertencia Si tu Python viene de Microsoft Store o de otro sitio no oficial y ves un error de tipo externally-managed-environment (PEP 668), es una protección del propio Python, no un fallo de Agent Reach. La solución sigue siendo pipx, como en el comando de arriba; si por algún motivo tampoco funciona, la alternativa documentada es crear un entorno virtual: 
py -3 -m venv $env:USERPROFILE\.agent-reach-venv
$env:USERPROFILE\.agent-reach-venv\Scripts\Activate.ps1
python -m pip install https://github.com/Panniantong/agent-reach/archive/main.zip
Qué debería ocurrir

Verás varias líneas de descarga y, al final, un mensaje similar a:

  installed package agent-reach 1.5.0, installed using Python 3.12.4
  These apps are now globally available
    - agent-reach
done! ✨ 🌟 ✨
Prueba
agent-reach --version

Debe responder con algo como Agent Reach v1.5.0 (o una versión posterior).

Si no ocurre
  • Si agent-reach no se reconoce como comando: cierra y reabre PowerShell (pipx necesita añadir su carpeta al PATH, igual que en el PASO 4).
  • Si ves un error de red: comprueba tu conexión a internet y que github.com no esté bloqueado por un firewall o antivirus.
PASO 8

Ejecutar la comprobación de solo lectura

Qué vamos a hacer

Pedirle a Agent Reach que revise tu sistema sin cambiar nada todavía.

Por qué

Así puedes ver qué falta antes de autorizar ningún cambio. Por defecto, agent-reach install solo mira, no cambia nada en tu sistema. Hace falta añadir --system explícitamente para que instale o configure algo. Esto es una medida de seguridad deliberada del proyecto.

Acción
agent-reach install --env=auto
Qué debería ocurrir

Un informe de texto que repasa: gh CLI, Node.js, mcporter, configuración de yt-dlp, y te dice qué falta.

Prueba

Que el comando termine sin errores de Python (tracebacks). Los avisos de "falta tal cosa" son normales en esta fase: son solo información.

Si no ocurre

Si ves un error de Python, repite los pasos 1 a 3 (verificación de Python/pip) antes de continuar.

PASO 9

Autorizar la instalación real de las piezas básicas

Qué vamos a hacer

Autorizar explícitamente a Agent Reach para que instale y configure las piezas zero-config: lector web (Jina Reader), YouTube, GitHub, RSS, búsqueda Exa, V2EX y Bilibili básico.

Por qué

Estas siete capacidades no necesitan ninguna cuenta ni contraseña, así que se activan todas de una vez con tu autorización.

Acción
agent-reach install --env=auto --system
Qué debería ocurrir

Verás un proceso más largo que el PASO 8: instala/comprueba mcporter, activa Exa a través de MCP (sin necesidad de clave), y al final te pregunta si quieres activar canales adicionales que necesitan inicio de sesión (Twitter, XiaoHongShu, Reddit, Facebook, Instagram). Por ahora responde que no a esos opcionales — los activaremos uno a uno en la sección de capacidades, cuando entendamos cada uno.

Prueba

Ejecuta el comando de diagnóstico (lo vamos a usar mucho a partir de ahora):

agent-reach doctor

Deberías ver marcas verdes (✅) junto a Web, YouTube, GitHub, RSS y Bilibili (búsqueda y detalle de vídeo).

Si no ocurre

Si algún canal zero-config aparece en rojo ([X]), agent-reach doctor imprime en ese mismo renglón qué falta y cómo arreglarlo. Sigue esa indicación concreta antes de continuar.

Previsualizar sin ejecutar Si prefieres solo previsualizar qué haría --system sin ejecutar nada todavía, puedes usar: 
agent-reach install --env=auto --dry-run

Configurar Agent Reach y primera prueba

"Configurar" es distinto de "instalar": instalar pone el programa en tu ordenador; configurar le dice qué servicios adicionales puede usar (por ejemplo, tu sesión de Twitter). Ahora mismo, tras el PASO 9, ya tienes activas las siete capacidades que no requieren cuenta. El resto son opcionales y se activan solo si tú lo pides.

La forma de activar canales opcionales es con la opción --channels, indicando uno o varios de estos nombres: twitter, xiaoyuzhou, xueqiu, xiaohongshu, reddit, facebook, instagram, bilibili, linkedin, opencli, o all para todos.

Por ejemplo, si más adelante quieres activar Twitter y XiaoHongShu a la vez:

agent-reach install --env=auto --system --channels=twitter,xiaohongshu

No vamos a ejecutar esto todavía. Más adelante iremos activando cada capacidad justo antes de probarla, para que entiendas exactamente qué hace cada paso.

Primera prueba

Después de instalar, vamos a conseguir una victoria real: no solo "no salió ningún error", sino ver a tu agente de IA leyendo información real de internet.

PASO 10

Comprobar el estado general con agent-reach doctor

Qué vamos a hacer

Pedir un resumen completo del estado de todas las capacidades.

Qué estamos probando

Que la instalación básica (PASO 9) quedó activa y accesible.

Acción
agent-reach doctor
Qué debería ocurrir

Un informe con una leyenda al principio (✅ disponible, [!] instalado pero necesita configuración o inicio de sesión, [X] no instalado) y, debajo, cada plataforma con su estado.

Cómo saber que funcionó

Debes ver ✅ en, al menos: páginas web, GitHub, YouTube, RSS y Bilibili (búsqueda y detalle).

Si no ocurre

Repite el PASO 9. Si un canal concreto sigue en rojo, copia el mensaje exacto que te da doctor en esa línea: siempre incluye una sugerencia de arreglo específica para ese canal.

PASO 11

Leer tu primera página web de verdad

Qué vamos a hacer

Usar la capacidad de lectura web (que no necesita ninguna configuración) para traer el contenido de una página real, limpio y en texto legible.

Por qué

Esta es la prueba más simple y más útil: confirma que Agent Reach realmente puede traer información de internet a tu agente.

Acción
curl.exe -s "https://r.jina.ai/https://es.wikipedia.org/wiki/Python"
Info Usamos curl.exe (con la extensión explícita) porque PowerShell tiene su propio alias llamado curl que no siempre se comporta igual que el programa real.
Qué debería ocurrir

Un bloque largo de texto en formato Markdown con el contenido del artículo de Wikipedia sobre Python: títulos, párrafos y enlaces, sin etiquetas HTML.

Prueba

Comprueba que el texto es legible (frases completas, no símbolos como <div> o <span>) y que menciona "Python" y "lenguaje de programación".

Si no ocurre
  • Si la respuesta está vacía: comprueba tu conexión a internet.
  • Si ves un error de certificado o de red: puede deberse a un firewall corporativo; la documentación oficial consultada no detalla soluciones específicas para ese caso.
Ejemplo Con esto puedes decir: "Agent Reach está funcionando." Tu ordenador acaba de traer, limpio y listo para leer, el contenido de una página web real usando exactamente la misma herramienta (Jina Reader) que usará tu agente de IA cada vez que le pidas que lea un enlace.

Capacidades I — Zero-config (sin cuenta)

Vamos a recorrer las 15 capacidades documentadas oficialmente. Empezamos por las siete que no piden ninguna cuenta ni configuración, y seguimos con las que necesitan que tú apruebes un inicio de sesión o una clave gratuita.

Para cada una encontrarás: qué hace, qué necesita, cómo se activa, ejemplos reales (con los comandos exactos que usa el proyecto), qué limitaciones tiene y qué errores son frecuentes.

Comprobar backend activo Cómo se comprueba qué herramienta está usando cada plataforma ahora mismo:

Este comando da la misma información que agent-reach doctor pero en un formato que un programa puede leer; el campo active_backend de cada plataforma te dice qué herramienta concreta está usando en este momento.

11.1 · Páginas web (lectura de cualquier URL)

Zero-config

Qué hace: convierte cualquier página web en texto limpio, en formato Markdown, quitando menús, anuncios y código HTML.

Para qué sirve: para que tu agente pueda "leer" cualquier enlace que le pases, sin atascarse con el diseño de la página.

Qué necesita: nada. Cero configuración.

Cómo se configura: no requiere configuración; queda activo tras el PASO 9.

Cómo se usa:

curl.exe -s "https://r.jina.ai/URL_COMPLETA"

EJEMPLO A — Leer una noticia (ejemplo mínimo)

Objetivo: obtener el texto de un artículo cualquiera.

Preparación: ninguna.

Acción:

curl.exe -s "https://r.jina.ai/https://es.wikipedia.org/wiki/Inteligencia_artificial"

Resultado esperado: texto en Markdown con el contenido del artículo.

Qué acaba de suceder: Agent Reach envió la URL a Jina Reader, un servicio que descarga la página, la limpia y devuelve solo el contenido legible.

EJEMPLO B — Comparar dos páginas (ejemplo práctico)

Objetivo: traer el contenido de dos páginas para que tu agente las compare.

Preparación: ten a mano dos URLs sobre el mismo tema.

Acción:

curl.exe -s "https://r.jina.ai/https://es.wikipedia.org/wiki/Python"
curl.exe -s "https://r.jina.ai/https://es.wikipedia.org/wiki/JavaScript"

Resultado esperado: dos bloques de texto, uno por página.

Qué acaba de suceder: ejecutaste la misma capacidad dos veces con URLs distintas; así es como tu agente reuniría información de varias fuentes antes de responderte.

Variación: prueba con una página en otro idioma; Jina Reader conserva el idioma original del texto.

Limitaciones: la documentación oficial consultada no especifica límites de tamaño de página ni de peticiones por minuto para este servicio.

Errores frecuentes: si la página exige haber iniciado sesión (por ejemplo contenido detrás de un muro de pago), el texto devuelto puede estar incompleto o vacío; esto no es un fallo de Agent Reach, sino una limitación de la propia página.

11.2 · RSS (cualquier fuente RSS/Atom)

Zero-config

Qué hace: lee fuentes RSS o Atom (las que usan blogs, medios de noticias y podcasts para publicar sus actualizaciones).

Para qué sirve: para que tu agente pueda revisar si un blog o medio tiene contenido nuevo, sin que tengas que visitarlo tú.

Qué necesita: nada. Cero configuración.

Cómo se usa: Agent Reach usa la librería de Python feedparser:

python3 -c "
import feedparser
for e in feedparser.parse('URL_DEL_FEED').entries[:5]:
    print(f'{e.title} - {e.link}')
"
Info En Windows, si python3 no funciona pero python sí, usa python en su lugar.

EJEMPLO A — Leer los últimos titulares de un feed (ejemplo mínimo)

Errores frecuentes: si la URL no es un feed válido, feedparser puede devolver una lista vacía en vez de un error explícito; conviene comprobar visualmente que la URL termina en algo como /feed, /rss o .xml.

11.15 · Xiaoyuzhou Podcast (小宇宙)

ffmpeg + Groq

Qué hace: transcribe episodios de podcast del servicio chino Xiaoyuzhou, convirtiendo el audio en texto completo.

Para qué sirve: para leer (en vez de escuchar) el contenido de un episodio de podcast.

Qué necesita: ffmpeg (para preparar el audio) y una clave gratuita de Groq (para la transcripción con inteligencia artificial Whisper).

Cómo se configura:

  1. Instala ffmpeg. En Windows 11, la forma más simple es con winget:
winget install ffmpeg
  1. Consigue una clave gratuita de Groq (no pide tarjeta de crédito):
    • Entra en https://console.groq.com
    • Inicia sesión con tu cuenta de Google o GitHub (o regístrate)
    • Ve a API Keys → Create API Key
    • Copia la clave (empieza por gsk_)
  2. Guarda la clave en Agent Reach:
agent-reach configure groq-key
  1. Activa el canal:
agent-reach install --env=auto --system --channels=xiaoyuzhou

Cómo se usa:

bash ~/.agent-reach/tools/xiaoyuzhou/transcribe.sh "URL_DEL_EPISODIO"
Advertencia Este script concreto se distribuye para entornos tipo Unix/Bash; en Windows puro, ejecútalo desde una terminal Bash disponible en tu sistema (por ejemplo, la incluida con Git for Windows) si bash no está disponible de forma nativa en tu PowerShell. La documentación oficial consultada no detalla una versión nativa de PowerShell para este script en concreto.

EJEMPLO A — Transcribir un episodio (ejemplo mínimo)

Objetivo: obtener el texto completo de un episodio de podcast.

Preparación: haber completado la configuración de arriba.

Acción:

bash ~/.agent-reach/tools/xiaoyuzhou/transcribe.sh "https://www.xiaoyuzhoufm.com/episode/ID_DEL_EPISODIO"

Resultado esperado: un archivo Markdown en la carpeta temporal del sistema (/tmp/ en el script original) con la transcripción completa en chino.

Qué acaba de suceder: el script descargó el audio, lo preparó con ffmpeg, lo envió a Groq (que ejecuta el modelo Whisper) y guardó el texto resultante.

EJEMPLO B — Transcribir con mejor puntuación (ejemplo práctico)

Objetivo: obtener una transcripción con puntuación y párrafos mejor organizados.

Preparación: igual que el ejemplo A.

Acción:

bash ~/.agent-reach/tools/xiaoyuzhou/transcribe.sh --polish "https://www.xiaoyuzhoufm.com/episode/ID_DEL_EPISODIO"

Resultado esperado: el mismo tipo de transcripción, pero pasada por un segundo modelo de IA gratuito que mejora la puntuación y la división en párrafos.

Qué acaba de suceder: añadiste un paso extra de "pulido" del texto; tarda unos segundos más (aproximadamente 7 segundos más para un episodio de 9 minutos, según la documentación del proyecto).

Variación: prueba con un archivo de audio local en vez de una URL: bash ~/.agent-reach/tools/xiaoyuzhou/transcribe.sh --polish ./mi_audio.mp3

Limitaciones: la cuenta gratuita de Groq permite aproximadamente 2 horas de audio por hora, y al superar ese límite hay que esperar unos 15 minutos; para episodios de más de 2 horas, la documentación recomienda procesarlos por partes. Whisper no distingue entre distintas personas hablando.

Errores frecuentes: si Groq da un error de límite alcanzado (código 429), el propio proyecto reintenta automáticamente incluyendo de nuevo las instrucciones de puntuación; si configuraste también una clave de OpenAI y usas explícitamente --allow-provider-fallback, el sistema puede enviar el mismo audio a OpenAI como respaldo (esto puede generar costes en OpenAI, así que solo actívalo si el contenido se puede compartir con ambos proveedores).

Experimentos

Estos experimentos están pensados para que veas con tus propios ojos por qué las cosas funcionan como funcionan, no solo que funcionan.

Experimento 1 — Qué pasa si guardas la cookie de Twitter pero no defines las variables de entorno

  1. Ejecuta agent-reach configure twitter-cookies y pega tu cookie exportada.
  2. Sin definir $env:TWITTER_AUTH_TOKEN ni $env:TWITTER_CT0, ejecuta directamente: 
    twitter feed -n 5
  3. Qué vas a observar: el comando falla o indica credenciales ausentes, aunque agent-reach doctor muestre Twitter como configurado.
  4. Por qué pasa esto: la documentación oficial lo aclara explícitamente: el valor que guarda agent-reach configure solo sirve para que doctor compruebe que existe una configuración; no la inyecta automáticamente en cada comando que ejecutes. Las variables de entorno hay que definirlas tú mismo en cada ventana de terminal donde vayas a usar Twitter.

Experimento 2 — Comparar la búsqueda vía bili-cli y vía OpenCLI para el mismo vídeo de Bilibili

  1. Ejecuta bili video BVxxxxxxxxx para un vídeo cualquiera.
  2. Ejecuta opencli bilibili subtitle BVxxxxxxxxx para ese mismo vídeo.
  3. Qué vas a observar: el primero te da metadatos (título, autor, duración) sin necesidad de sesión; el segundo te da el subtítulo completo, pero requiere que Chrome esté abierto con la extensión conectada.
  4. Por qué pasa esto: son dos herramientas distintas, cada una responsable de una parte distinta de la información de Bilibili; ninguna de las dos lo hace todo por sí sola.

Experimento 3 — Provocar (de forma controlada) el fallo conocido de twitter search

  1. Ejecuta twitter search "prueba" -n 1 un par de veces seguidas.
  2. Si falla, sigue la cadena de alternativas documentada en la sección 11.8: reintentar, actualizar la herramienta, usar opencli twitter search, o recurrir a twitter feed/twitter user-posts.
  3. Qué acabas de comprobar: que Agent Reach no oculta los fallos conocidos, sino que los documenta junto con un plan concreto de qué hacer cuando ocurren — esto es justo lo que hace agent-reach doctor quintaesencialmente: decirte qué funciona ahora mismo, no lo que debería funcionar en teoría.

Combinar capacidades

Las capacidades individuales se vuelven mucho más útiles cuando las encadenas. Aquí tienes dos ejemplos de cómo tu agente combinaría varias.

Combinación A — Investigar un proyecto de código abierto a fondo

  1. GitHub (11.3): gh repo view owner/repositorio para entender de qué trata.
  2. Páginas web (11.1): curl.exe -s "https://r.jina.ai/URL_DE_LA_DOCUMENTACION" para leer su documentación oficial si vive fuera de GitHub.
  3. Búsqueda web (11.7): mcporter call exa.web_search_exa query="opiniones sobre NOMBRE_DEL_PROYECTO" numResults=5 para ver qué opina la gente fuera del propio proyecto.

Resultado: una visión completa —qué es, qué dice su propia documentación, y qué opina gente externa— sin abrir un navegador.

Combinación B — Investigar cómo reacciona la comunidad a un lanzamiento de producto

  1. Reddit (11.9): opencli reddit search "nombre del producto" -f yaml para ver debates técnicos.
  2. Twitter (11.8): twitter search "nombre del producto" (o su alternativa vía opencli) para ver reacciones en tiempo real.
  3. XiaoHongShu (11.10): opencli xiaohongshu search "nombre del producto" -f yaml si el producto también tiene presencia en el mercado chino.

Resultado: una foto de cómo distintas comunidades, en plataformas muy distintas, están hablando del mismo tema — algo que tardarías mucho más tiempo en reunir manualmente visitando cada red por separado.

Fácil

Proyecto final — Informe de vigilancia de un tema, de principio a fin

Este proyecto junta prácticamente todo lo que has aprendido en este tutorial.

Objetivo: producir, con tu agente de IA, un informe completo sobre un tema de tu elección, combinando fuentes técnicas, sociales y de noticias, y guardarlo como un documento que puedas releer más tarde.

Capacidades a combinar (elige al menos 5)

  • Páginas web (11.1) — para leer artículos completos.
  • RSS (11.2) — para fuentes que sigues habitualmente.
  • GitHub (11.3) — si el tema tiene relación con algún proyecto de código abierto.
  • YouTube (11.4) o Bilibili (11.5) — si existen vídeos relevantes.
  • Búsqueda web (11.7) — para descubrir fuentes que no conocías.
  • Reddit (11.9) o Twitter (11.8) — para el pulso de la comunidad.

Pasos

  1. Define el tema con precisión. No "inteligencia artificial" (demasiado amplio), sino algo como "herramientas para que agentes de IA naveguen por internet en 2026".
  2. Reúne fuentes técnicas: usa GitHub y búsqueda web para encontrar proyectos y documentación relevantes.
  3. Reúne el pulso social: usa Reddit y/o Twitter para ver qué opina la gente que ya usa este tipo de herramientas.
  4. Reúne contenido audiovisual (opcional): si encuentras un vídeo relevante, extrae sus subtítulos y resúmelos.
  5. Pide a tu agente que redacte un informe con esta estructura: introducción del tema, qué dicen las fuentes técnicas, qué dice la comunidad, y una conclusión con tu propia valoración de hacia dónde va el tema.
  6. Guarda el informe como un archivo Markdown en tu ordenador, para poder consultarlo más adelante o compararlo con una versión futura.
Ejemplo Cómo saber que lo conseguiste: si al leer el informe final aprendes algo que no sabías antes de empezar, y si podrías repetir todo el proceso para un tema distinto sin tener que volver a leer este tutorial, el proyecto está completo.

La documentación oficial insiste en que este comando da, para cada plataforma con más de una herramienta posible (XiaoHongShu, Reddit, Bilibili, Twitter), el nombre exacto de la herramienta que está usando en este momento (当前后端, "backend actual"), y un mensaje de arreglo específico si algo falla — no un mensaje genérico.

Seguridad

Agent Reach maneja información sensible: cookies de sesión de tus propias cuentas y, si activas Xiaoyuzhou, una clave de API de Groq. Estas son las prácticas de seguridad reales documentadas por el proyecto:

  • Usa una cuenta secundaria para Twitter/X, no tu cuenta principal. Es una recomendación explícita del propio proyecto: el acceso automatizado por cookie puede llevar a la plataforma a limitar la cuenta.
  • Nunca compartas tu cadena de cookies exportada con nadie que no sea tu propio agente de IA local. Esa cadena da acceso completo a tu sesión en esa web, igual que una contraseña.
  • Para automatización sin supervisión, usa el modo --stdin al ejecutar agent-reach configure, en vez de escribir la cookie como argumento visible del comando; así evitas que quede guardada en el historial de la terminal.
  • Dónde se guarda todo: tus credenciales quedan en C:\Users\TU_USUARIO\.agent-reach\config.yaml. Ese archivo no debe compartirse ni subirse a ningún repositorio de código.
  • Sobre los permisos del archivo de configuración: en sistemas tipo Unix, Agent Reach restringe el acceso a ese archivo automáticamente (equivalente a chmod 600, solo tu usuario puede leerlo); la documentación del propio código señala que esa restricción concreta se omite en Windows, porque el sistema de permisos de Windows funciona de otra forma. En la práctica, la protección real en Windows es que solo tu propia cuenta de usuario tiene acceso a tu carpeta personal (C:\Users\TU_USUARIO\) por defecto.
  • No trates los datos de mercado de Xueqiu como asesoramiento de inversión: pueden llegar con retraso.
  • Si compartes tu agente o tu ordenador con otras personas, cualquiera con acceso a tu carpeta de usuario podría leer config.yaml y usar tus sesiones. Trátalo con el mismo cuidado que un gestor de contraseñas.
  • Si encuentras una vulnerabilidad de seguridad real en el propio Agent Reach (no un problema de uso, sino un fallo del programa), el proyecto pide reportarlo de forma privada a través de GitHub Security Advisories (https://github.com/Panniantong/Agent-Reach/security/advisories/new), nunca en un Issue público.

Actualización, desinstalación y resumen final

Actualización

Agent Reach se actualiza con dos pasos: revisar si hay una versión nueva, y aplicarla.

PASO 12

Comprobar si hay una versión más reciente

Acción
agent-reach check-update
Qué debería ocurrir

Si ya tienes la última versión, verás un mensaje indicándolo; si no, verás qué ha cambiado en la versión nueva.

PASO 13

Actualizar Agent Reach

Acción (con pipx, la forma que usamos en este tutorial)
pipx install --force https://github.com/Panniantong/agent-reach/archive/main.zip
PASO 14

Actualizar las herramientas que ya tienes instaladas

Este paso solo actualiza lo que ya tienes en tu sistema; no instala nada nuevo que no hayas pedido:

pipx upgrade twitter-cli
pipx upgrade bilibili-cli
pipx upgrade xiaohongshu-cli
npm update -g mcporter
npm update -g "@jackwener/opencli"
Info Solo ejecuta las líneas correspondientes a las herramientas que realmente hayas instalado; el resto no hace nada si la herramienta no existe en tu sistema.
PASO 15

Verificar que todo sigue funcionando

agent-reach version
agent-reach doctor

Qué debería ocurrir: el mismo tipo de informe que viste en el PASO 10, con los canales que ya tenías activos otra vez en verde.

Un detalle importante de cómo se comporta Agent Reach al actualizar Nunca desinstala por su cuenta ninguna herramienta que ya tuvieras, aunque exista una alternativa mejor. Si prefieres cambiar de una herramienta a otra (por ejemplo, pasar de una herramienta antigua a OpenCLI), es una decisión que tomas tú explícitamente, no algo que ocurra solo.

Desinstalación

Puedes deshacer, paso a paso, exactamente lo que hiciste en este tutorial.

PASO 16

Ver qué se eliminaría, sin borrar nada todavía

agent-reach uninstall --dry-run

Qué debería ocurrir: una lista de lo que se borraría si confirmas: tu carpeta de configuración (~/.agent-reach/, con todas tus cookies, tokens y claves guardadas) y los archivos de guía instalados para tu agente de IA. Con --dry-run, nada se borra todavía.

PASO 17

Eliminar la configuración de Agent Reach de verdad

agent-reach uninstall

Si prefieres conservar tu configuración (cookies, tokens) y solo quitar los archivos de guía del agente:

agent-reach uninstall --keep-config

Qué debería ocurrir: un resumen de lo que se eliminó: la carpeta ~/.agent-reach/ con todas tus credenciales, y los archivos de guía (SKILL.md) instalados para tu agente de IA en las carpetas que Agent Reach detectó.

PASO 18

Eliminar el propio programa agent-reach (opcional)

pipx uninstall agent-reach
PASO 19

Eliminar las herramientas individuales que instalaste (opcional)

Solo si quieres una limpieza completa; ninguna de ellas se elimina automáticamente porque otros programas tuyos podrían seguir usándolas:

npm uninstall -g mcporter
npm uninstall -g "@jackwener/opencli"
pipx uninstall twitter-cli
pipx uninstall bilibili-cli
pipx uninstall xiaohongshu-cli
Info Node.js, gh CLI, pipx y Python en sí no los instaló Agent Reach: si quieres desinstalarlos también, se hace desde "Aplicaciones instaladas" en la Configuración de Windows 11, igual que cualquier otro programa.

Qué hemos aprendido

  1. Entendido qué problema resuelve Agent Reach: darle a tu agente de IA acceso real a internet y a redes sociales, sin que tengas que configurar cada plataforma por separado.
  2. Preparado Windows 11 desde cero: Python, pipx, Node.js y GitHub CLI.
  3. Instalado y comprobado Agent Reach con su propio comando de diagnóstico, agent-reach doctor.
  4. Conseguido tu primera lectura real de una página web con tu agente.
  5. Recorrido las 15 capacidades documentadas oficialmente, con ejemplos reales de cada una: desde las que no piden ninguna cuenta (páginas web, RSS, GitHub, YouTube, Bilibili, V2EX, búsqueda web) hasta las que requieren sesión iniciada (Twitter, Reddit, XiaoHongShu, Facebook, Instagram, Xueqiu, LinkedIn, Xiaoyuzhou).
  6. Practicado con ejercicios y experimentos que muestran no solo qué hacer, sino por qué funciona así.
  7. Combinado varias capacidades en proyectos progresivos, hasta un proyecto final de investigación completa sobre un tema de tu elección.
  8. Sabes cómo diagnosticar problemas, mantener actualizado tu sistema, y desinstalarlo todo de forma limpia si alguna vez lo necesitas.

A partir de aquí, la mejor forma de seguir aprendiendo es simplemente pedirle a tu agente de IA tareas reales que necesiten información de internet, y observar (con agent-reach doctor como tu herramienta de diagnóstico) qué capacidad está usando en cada caso.
